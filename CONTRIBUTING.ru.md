# Участие в проекте

Спасибо, что заглянули. Проект небольшой, мейнтейнер один, поэтому коротко: перед тем как писать что-то большое, заведите issue, и рассчитывайте, что ответ придёт скорее за пару дней, чем за пару часов.

## С чего начать

- **Баги** — через [форму багрепорта](https://github.com/orloffas/macyad/issues/new?template=bug_report.yml). Она просит версию rclone, версию macOS и запись журнала: без них сообщение о проблеме синхронизации разобрать невозможно. В **Settings → О программе** есть кнопка, которая копирует всё это разом.
- **Вопросы** — через [форму вопроса](https://github.com/orloffas/macyad/issues/new?template=question.yml). Писать можно по-русски.
- **Проблемы с безопасностью** — через [приватный отчёт](https://github.com/orloffas/macyad/security/advisories/new), не публичным issue. Подробности в [SECURITY.ru.md](SECURITY.ru.md).
- **Крупные изменения** — сначала обсудите. PR, переписывающий модель синхронизации, не будет принят по одному лишь качеству кода: модель здесь и есть продукт.

## Что точно не примут

Не потому что идея плохая, а потому что она противоречит тому, чем это приложение является:

- Автоматическая двусторонняя синхронизация и любой плановый запуск, разрешающий конфликт самостоятельно.
- Что угодно, что передаёт файлы без baseline-проверки перед этим.
- Телеметрия, аналитика, отправка отчётов о падениях на сервер, автообновление.
- Вендоринг `rclone` или замена его на собственный клиент Яндекс Диска.

## Сборка

```bash
brew install rclone xcodegen
git clone https://github.com/orloffas/macyad.git
cd macyad
xcodegen generate          # Macyad.xcodeproj генерируется, в репозиторий не коммитится
open Macyad.xcodeproj
```

Полный цикл «собрать — установить — запустить» делает `./script/build_and_run.sh`. Если пересобираете часто, настройте [локальный сертификат подписи](docs/local-signing.ru.md) — иначе macOS будет заново спрашивать доступ к папкам после каждой сборки.

## Тесты

```bash
./script/test.sh unit      # MacyadCore — то, что гоняет CI
./script/test.sh ui        # плюс XCUITest; нужен разблокированный, не спящий экран
```

Две вещи, которые стоит знать до отправки PR:

- Unit-схема **не компилирует вьюхи**. После правок в `Macyad/Views/` собирайте ещё и app-таргет: `xcodebuild build -project Macyad.xcodeproj -scheme Macyad -destination 'platform=macOS'`.
- UI-тесты проверяют `isHittable`, а не только существование элемента. У панели, которая не смогла разложиться, дерево доступности остаётся полным, поэтому проверки существования проходят на окне, отрисованном пустым. Это не паранойя — именно так настоящий баг пережил зелёный прогон.

## Код

- Swift 6, deployment target macOS 14. Оба заданы в `project.yml` — править нужно его, а не сгенерированный `.xcodeproj`.
- Любая строка, которую видит пользователь, идёт через `AppCopy` и существует на английском и русском. `NSLocalizedString` в этой кодовой базе не используется.
- Комментарии объясняют «почему», а не «что». Если строка выглядит странно и это намеренно — напишите, почему намеренно.
- В каждом каталоге есть `AGENTS.md` с описанием того, что там лежит, и специфичных граблей. Прочитайте тот, что рядом с изменяемым кодом; если ваша правка делает его неверным — обновите.
- Сообщения коммитов и описания PR — на английском.

## Помощь AI

Проект пишется с активным использованием AI-ассистентов — отсюда трейлеры
`Co-Authored-By` в истории коммитов. Вам ими пользоваться тоже можно.

Требование в обоих случаях одно: за присланный код отвечаете вы. Умейте
объяснить, что он делает и почему написан именно так, и прогоняйте тесты перед
открытием PR. Патч, которого никто не понимает, — обуза независимо от того, кто
или что его написал.

## Pull request'ы

`main` защищена: работа идёт в ветке и через PR, включая работу мейнтейнера. CI прогоняет unit-тесты и собирает app-таргет; оба должны быть зелёными.

Один PR — одно изменение. Два несвязанных исправления — это два PR: их быстрее ревьюить и чище откатывать.

Если правка меняет поведение, обновите **обе половины** `README.md` — английскую и русскую секцию под ней. Они должны говорить одно и то же; изменить одну и забыть вторую — незакрытая задача.

Финальное решение по объёму и дизайну — за мейнтейнером. Если PR отклонён, дело обычно в том, что он не вписывается, а не в качестве.
